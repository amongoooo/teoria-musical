# Teoría Musical — guía para Claude

App web gratuita (GitHub Pages) para aprender teoría musical y producción en FL Studio, al estilo Brilliant: 10 módulos, lecciones cortas e interactivas con audio y retos prácticos en FL Studio.

- Plan completo: https://claude.ai/artifact/BPJh8PxMqQw6NAyuBgD16i
- Página publicada: https://amongoooo.github.io/teoria-musical/

## Preferencias del usuario (¡seguir siempre!)

- **Responder siempre en español.**
- **Indicar el porcentaje de avance del proyecto en cada respuesta**, y también el **avance aproximado de la tarea en curso** (p. ej. «Tarea actual: ~40 %»).
- **Hacer push después de cada commit.**
- **Hacer merge a `main` siempre que se pueda** (crear el PR de la rama y unirlo al terminar cada tarea, para que se publique).
- **Al terminar una tarea, mandar el link de la página:** https://amongoooo.github.io/teoria-musical/
- **Al terminar, recomendar** para la siguiente tarea: chat (seguir en el mismo o abrir uno nuevo), modelo, nivel de esfuerzo y el prompt listo para copiar.
- El usuario trabaja **casi siempre desde el celular**: evitar pasos que necesiten terminal. Todo debe poder hacerse desde GitHub web o pidiéndoselo a Claude.
- **Explicar lo mínimo cómo funciona la app**: que sea intuitiva (resaltar, color, movimiento) en vez de textos de instrucciones.
- **Diseño pensado primero para celular** (mobile-first): botones grandes, nada que dependa de hover o teclado físico.

## Stack

- **Vite + React en JavaScript** (`.jsx`, sin TypeScript) · **Tailwind CSS v4** (`@tailwindcss/vite`, tema en `src/index.css`).
- **Tone.js** para el audio (piano con samples Salamander + sintetizador de respaldo; batería sintetizada).
- **motion** (Framer Motion) con resortes: presets en `src/ui/movimiento.js`; todo lo tocable es `src/ui/Pulsable.jsx`.
- **Tonal.js** (`tonal`) para la teoría: intervalos, fórmulas y escalas (`src/theory/intervalos.js`: pasos, fórmulas e intervalos con nombre; `src/theory/escalas.js`: escalas mayor, menor y pentatónicas, grados, relativas y melodías por grados con `Scale`; círculo de quintas y armaduras con `Key`; `src/theory/acordes.js`: tríadas, nombres y cifrado con `Chord`; acordes de la tonalidad con `Key` (`diatonicos`, `ROMANOS`), inversiones, voicing abierto (`abierto`), funciones T · S · D (`FUNCIONES`, `funcionDe`, `funcionesDe`, `notasComunes`) y séptimas (`SEPTIMAS`: dom7, maj7, m7; `TIPOS_ACORDE`, `acordeDeGrado(t, 'V7' | 'ii7' | 'Imaj7' | 'I7')`, `TRITONO`, `resolucionV7`) y cadencias (`CADENCIAS`, `cadenciaDe`)). Previsto: **@tonejs/midi**.
- **localStorage** para progreso, opciones y entrenamiento de oído (sin servidor ni cuentas).
- Estilo: minimalista, mucho espacio, tipografía grande. **Paleta por significado** (gris = estructura/bloqueado, verde = bien con ✓, oro = fíjate con bombilla, **un color por ÁREA** —Ritmo naranja, Melodía turquesa, Armonía violeta, Letras rosa, Producción rojo coral; `src/content/areas.js`—: módulos, rutas, prácticas y herramientas llevan el de su área), **íconos mínimos** propios, **fuentes por rol** (Bricolage Grotesque `font-titulo`, Figtree texto, DM Mono `font-dato`, Pixelify Sans `font-juego`) y **tres materiales**: vidrio = la app (lo que flota: cabeceras, botón principal de la barra de abajo, botones de navegar), superficie = la lección, color = el significado (con opción «Opaco» en Opciones). Todo en la skill de diseño.

## Notas técnicas

- `vite.config.js` usa `base: '/teoria-musical/'` (GitHub Pages). Las rutas a archivos de `public/` usan `import.meta.env.BASE_URL`.
- El audio solo empieza tras un gesto del usuario (`startAudio()` en `src/audio/engine.js`; iOS lo exige).
- **Despliegue automático**: cada push a `main` ejecuta `.github/workflows/deploy.yml` (Node 20, `npm ci`, `npm run build`, publica `dist`; en Settings → Pages → Source debe estar **GitHub Actions**).
- **App instalable (PWA) y sin internet**: `public/manifest.webmanifest` + íconos en `public/iconos/`; en `npm run build` el plugin `swApp` de `vite.config.js` genera `dist/sw.js` desde `src/pwa/sw-plantilla.js` con la lista de archivos del build y una versión (hash). Guarda toda la app y los samples del piano (`src/audio/salamander.js`); páginas: primero la red (4 s) y sin red la copia; archivos: primero la copia. Cada despliegue con cambios crea una versión nueva y borra la vieja. Solo se registra en producción (no en `npm run dev`). Si cambias los íconos, regenera los PNG desde los SVG.
- **Versión de la app** (arriba en Opciones): `v.1.AA.MM.DD.HHMM` con la fecha y hora de compilación en la hora del usuario (Ciudad de México, UTC−6); la calcula `versionApp()` en `vite.config.js` y llega como `__VERSION_APP__` (`define`). Se actualiza sola en cada despliegue.
- Comandos: `npm run dev`, `npm run build`, `npm run preview` (abre `/teoria-musical/`).
- **Lecciones**: un archivo de datos por lección en `src/content/modulo-XX/`, registrado en `src/content/index.js`. El visor muestra un paso por pantalla y un botón grande abajo que cada ejercicio controla con `setAccion` (Comprobar → retroalimentación → Continuar; solo esas dos palabras, más «Atrás» con el gesto; `avanza: true` = el paso está resuelto). El botón también pasa de paso con un gesto (`useGestoBoton`): volver siempre; avanzar si está resuelto (o en modo administrador). **Ahora sí se puede fallar** (pedido del usuario, 2026-11-15; propuesta: https://claude.ai/artifact/DMiDeDCE8uqfPF6xBdC9oc): cada pregunta (ronda) tiene **dos intentos**; el 1.º error es **oro** (pista, sin dar la respuesta; lo elegido queda tachado); el 2.º enseña la **respuesta correcta en rojo** (`mal-*`, ícono `Repaso`), cuenta como mal y la ronda va al **repaso del final** (`fallo(r)` → `[paso, ronda]` en `falladas` del progreso, solo en el dispositivo). Con **2 opciones**, un solo intento. Al terminar el último paso, el visor repite cada ronda roja (`soloRonda`; cabecera «Repaso», una sola vuelta) y la pantalla final dice «Repaso: x de y». **Completada** al acabar el repaso (fallar no bloquea nada); **aciertos** = a la primera. No cuentan: explicaciones, siente, retos, explorar, frecuencia, dibujar libre y **Toca al pulso**; la prueba rápida (`noLoSe`) y los entrenadores no cambian. En los pasos de piano el aviso es **plegable** (solo «Esa es Fa4.»; la explicación al tocarlo). `pista` en un paso = botón de bombilla junto a la etiqueta.
- **Prueba rápida «¿Ya lo sabes?»** (`content/pruebas/`, `pages/Prueba.jsx`, `components/yaLoSabes.js`): los cuadritos de módulos y rutas entran directo; en el globo de la **insignia** del camino, mientras quede algo por saltar, el botón principal es «¿Ya lo sabes?» (en lugar de «Ir a…»); una pregunta por lección pendiente (en una ruta, la del tramo en el que vas) con «No lo sé»; al final se eligen las lecciones a saltar. Saltada = `{ completada: true, saltada: true }` (`saltarLecciones` en `progress/progreso.js`): cuenta como hecha en todo; si se hace de verdad, `completarLeccion` le quita `saltada`; al sincronizar, `saltada` solo si ningún dispositivo la hizo. ✓ en contorno (`MarcaBien saltada`) y «Saltada con la prueba» / «Hacerla» en el globo.
- **Números por área** (pedido del usuario, 2026-11-16): por dentro, módulos 1–11 e ids de lección '4.1', 'L3' (URLs, progreso); lo que se VE: módulo «Armonía 2» y lección **«A2.1»** (inicial del área: M Melodía, R Ritmo, A Armonía, L Letras, P Producción). En el camino de un módulo, las islas muestran solo su posición (1, 2, 3…). En textos para el usuario, nombra lecciones y módulos con `codigoLeccion` / `nombreModulo` (o el código escrito: «en la M2.2»), nunca con el id.
- **Desbloqueo** (`estadoLeccion` en `content/index.js` → `proximamente | hecha | empezada | nueva | bloqueada`): progresivo dentro de cada módulo; entre módulos no se bloquea; las URLs directas no se bloquean.
- **Prerrequisitos suaves** (`content/catalogo.js` → `faltanRequisitos` de `content/index.js`): al empezar una lección **desde cero** fuera de rutas y curso, si le falta un prerrequisito directo, sale **«Antes te conviene»** (`AntesTeConviene` en `pages/Leccion.jsx`: ir a esa lección, «¿Ya lo sabes?» = `#/prueba/leccion/ID`, o seguir). Las rutas y el curso abren `rutas.leccionGuiada(id)` (`#/leccion/ID/guiada`) y no avisan; tampoco el modo administrador. Las pruebas de Playwright que abren una lección directo usan `/guiada`.
- **Modo administrador** (Opciones → Administrador, con PIN; huella SHA-256 en `progress/admin.js`): ninguna lección bloqueada y, en una lección, la barra de pasos abre «Ir al paso» para saltar entre pasos; el gesto del botón avanza sin responder. En el entrenador de oído: todos los niveles abiertos y, al sonar, la respuesta se señala en oro (el piano va a su octava; no se presiona).
- **Computadora**: **Enter** presiona el botón de abajo (Comprobar / Continuar / Empezar), salvo en campos de texto u hojas abiertas; la **rueda del mouse** mueve los carruseles, una muesca = un paso sin pausa (`ui/useRuedaMouse.js`; quien lo usa suma al destino, no a lo que se ve a medio camino: ruedas del arranque, barra de octavas, navegador de módulos; en el camino, solo el scroll de lado).
- **Módulo abierto desde Aprender › Módulos** (pedido del usuario): su cabecera lleva la flechita ‹ de vuelta a Módulos en lugar de la casita (`volverDeModulo` de `router.js`).
- **Pestañas** (`components/BarraPestanas.jsx`): solo en Herramientas, Entrenar (id interno `practicar`; recuerda el último tipo), Inicio, Aprender y Configuración (Inicio ya no lleva engrane); dentro de un módulo, ruta o bloque la píldora se vuelve la barra de puntitos (casita = Inicio). **Aprender** = Curso | Rutas | Módulos (2026-11-16; el viejo `#/aprender/biblioteca` abre Módulos; el nivel de cada lección sale en el globo de su isla).
- **Meta guiada** (`progress/metaGuiada.js`): «Practicar» en una meta de ruta o bloque la recuerda (solo en memoria); al cumplirla en oído, ritmo o vocabulario sale «¡Meta cumplida!» y «Continuar» vuelve al camino.
- **Botones de arriba**: ✕ = salir de una lección o de una hoja; **flechita ‹** (`Atras`) = volver al apartado anterior (los entrenamientos de oído, ritmo y letras y sus paneles vuelven a **Entrenar** con su tipo elegido: `rutas.practicar(tipo)`); casita = Inicio.
- **localStorage**: `teoria-musical:progreso:v1` → `{ lecciones: { '1.1': { paso, completada, aciertos, total, saltada?, falladas? } }, retos: { '1.1': { hecho, nota }, 'M1': { hecho } }, pruebas: { 'M3' | 'T-triadas': { fecha, aciertos, total } } }` (`pruebas` no se sincroniza) · `teoria-musical:opciones:v1` (`tema`: claro | oscuro | sistema | programa, `programa`: `{ claro, oscuro }` en minutos, `reloj`: 24 | 12, `vidrio`: desenfoque | opaco, `contraste`: normal | alto (clase `contraste-alto`; también con «Aumentar contraste» del sistema), `octavas`: vista | teclas, `gesto`: pagina | invertido, `admin`: modo administrador) · `teoria-musical:oido:v1` (entrenador; por modo, forma `v: 2`: `nivel`, `nivelMax`, `superado: { nivel: dificultad }` (dominio), `ventana: [{ b, e, d }]`, `legado` (nivelMax de antes de la migración), `items`; ajustes: `juego`, `multiplicador`, `cadaAciertos`, `segundos`, `octavas` o `dificultad` (Acordes, Funciones), `vidas` (0 = Escalada, 21 = ∞), `respuesta`, `cifrado`, `direccion`; ritmo además `tempo`, `pad`). · `teoria-musical:ritmo:v1` y `teoria-musical:letras-vocab:v1` (misma forma que el de oído; el vocabulario además `repaso: { palabra: [caja, 'AAAA-MM-DD'] }`, `nuevas`, `temas`) · `teoria-musical:letras:v1` (cuaderno, solo en el dispositivo) · `teoria-musical:circulo:v1` (`{ tonalidad: 'G' }`, la última del explorador) · `teoria-musical:caja:v1` (`{ patron, bpm }` de la Caja de ritmos) · `teoria-musical:novedades:v1` (`{ visto: id }`, la última novedad abierta) · `teoria-musical:xp:v1` (`dispositivo`, `libro: { dispositivo: { día | 'total' | 'antes': { área: xp } } }`, `cansancio: { dia, s }`, `bonos: { dia, lista }`, `visto`: último nivel celebrado; en «Tu progreso» viaja compacto como `x`).
